Connect your
agent’s history.

After the MCP release, one command connects Claude Code or Codex. No source checkout or build step. Your client starts Runlens; the viewer can stay closed.

MCP is not on npm yet. The commands below are for after the MCP release. Requires Node.js 20+ and your agent’s CLI. To test today, open the source preview instructions below. These examples use a macOS/Linux shell.

Claude Code

After release: register privately for this project, then check the connection.

claude mcp add --scope local --transport stdio runlens -- \
  npx -y runlens@latest mcp --project "$PWD"
claude mcp list

Local scope keeps machine-specific paths out of the shared project config. Reconnect Claude Code and check /mcp before trying a question.

Codex

After release: save this project’s server in your Codex configuration.

codex mcp add runlens -- \
  npx -y runlens@latest mcp --project "$PWD"
codex mcp get runlens --json

Restart or reconnect Codex after registration. This entry keeps its configured project even when you open Codex in another folder.

"$PWD" captures the folder you are in at registration. You don’t need to type its path. Access stays fixed to that project; agents cannot approve another project themselves. Use a different server name for another project, or configure an explicit --allow-project grant and reconnect.

Try the unpublished source preview

Developer setup for testing before the npm release. Already have the source? Start with npm install inside your Runlens checkout. The RUNLENS_CLI variable locates this unpublished build only. 

git clone https://github.com/Priyadharshan0903/Runlens.git
cd Runlens
npm install
npm run check
export RUNLENS_CLI="$PWD/dist/cli.js"

In this same terminal, change into the project whose history you want. Choose the matching registration command below. Keep your built Runlens checkout at its saved location, rebuild after source changes, and reconnect your client. 

# Claude Code source preview
claude mcp add --scope local --transport stdio runlens -- \
  node "$RUNLENS_CLI" mcp --project "$PWD"
claude mcp list
# Codex source preview
codex mcp add runlens -- \
  node "$RUNLENS_CLI" mcp --project "$PWD"
codex mcp get runlens --json

Choose one setup per client. If runlens is already registered, review and update its existing configuration or use a distinct server name.

A few details.

Before you open your first run.

Which agents does it support?

Claude Code and Codex local history, including supported Codex CLI and editor sessions. Cursor history is not supported yet. Planned MCP client compatibility is separate from reading an agent’s own history.

Does it need an account or API key?

No. The current viewer reads local transcript files. It does not call a model or upload your sessions. Installing the npm package requires access to the npm registry.

Does it change my session files?

No. Transcripts are read-only. Your notes, tags, pins, and preferences are stored locally in the browser. You can export sessions as Markdown or JSON.

Does a green tool call prove the task worked?

No. Runlens shows recorded activity. File changes are recorded operations, not a final Git diff. Usage and cost appear only when recorded; Codex token totals cover the main agent only.

Can I connect an agent through MCP today?

Yes, using the source preview. MCP setup includes copyable Claude Code and Codex commands. MCP is not in the npm release yet. The client starts a read-only server; selected history can reach its model provider.
